# AUDIT_CODE: Strong Years app, pipeline workers, n8n, schemas

Independent security and QA audit, Sep 30 2026. Scope: `app/`, `workers/`, `n8n_core_workflow.json`, `schema.sql`, `app/supabase/migrations/`, `tools/build_content.py`, `.github/workflows/`. No repo files were edited. The probes were scratch tests and a scratch server, run outside the repo. Running `tools/build_content.py` as instructed regenerated its own outputs (HOOKS.md, SCRIPTS.md, ADS_SCRIPTS.md, SCRIPTS_COVERAGE.md, `data/content/*.json|csv|md`).

**Counts:** 4 critical · 12 high · 14 medium · 15 low (45 total).

"Confirmed" means it was reproduced by a probe (scratch vitest against the real modules, a live `next start` demo server, FastAPI TestClient, or the Stripe SDK). The other findings come from code review.

## 3. Checklist verdicts

**Security**
- Stripe signature verification: correct when the secret is set, but **fails open when the secret is missing (H5)**.
- Webhook idempotency: sequential duplicates are handled (`stripe_events` PK). In-flight redeliveries are not (L2), and the success-redirect path races the webhook (H8).
- `/app` and `/admin` auth: middleware plus `requireMember` and basic auth are in place. **No membership entitlement check (H2).** The success URL is a reusable login (M2). Magic links are single-use and hashed, but the plaintext token sits in the outbox (M6).
- Secrets logged: no API keys are logged. Magic tokens and gift codes are in the outbox (M6). The CAPI token is in a URL (L10).
- App RLS (members vs other members / crisis logs): **OK.** anon/authenticated have no table grants, so `crisis_events` and `chat_messages` are service-role only. There is a latent column over-grant (M13). **Pipeline schema RLS is critical (C3).**
- Chat: crisis bypasses (C2), weak output and scope guards (M14), PII retention and alerts (M6). The system prompt structure is sound (hard rules, memory in the system prompt) but was not dynamically tested (no API key).
- Rate limiting: none (M5).
- CSRF: OK. `SameSite=Lax` session cookie, server actions have Next.js origin checks, and there are no state-changing GETs besides the logins (M2).
- Open redirects: none. `success_url` and `cancel_url` are built from env plus a validated offer code, and `lead` redirects keep a fixed path. Only the login-page link injection applies (L1).
- Price and arm integrity: the server computes every amount, bumps are allowlisted, and the arm is forced to B in blitz mode. The only client lever is the visitor-cookie cell (L5).
- Worker auth / SSRF / ffmpeg: auth fails open, SSRF and local file read are confirmed, and path traversal is confirmed (H9). **No command injection:** subprocess uses list-form argv with no shell, and filter values are float-cast.

**Money correctness**
- Arm stickiness: OK (FNV hash of a 365-day `sy_vid` cookie, and the cell is logged on intent and membership).
- $25/$30 cells and the cap-close switch to $35: logic is correct in `resolveFoundingOffer`. The cap is soft under concurrency (low), and the displayed-vs-charged price can differ at the switch (M1).
- Bumps and upsells: bumps are correct (one-time lines on the first invoice). Upsells have no idempotency and errors are uncaught (M8).
- Gift non-renewing: correct (payment mode, no subscription), but the gift **never expires** and it **hijacks the cancel flow** (H3).
- Refund and guarantee: **broken** (C4, H1, H12).
- Cancel flow at most two screens: OK in structure, but it can target the wrong membership (H3).
- Consent logging stores the exact terms shown: **not guaranteed**, because the terms are re-rendered server-side (M1).
- 48h reminder timing: the hourly cron window is fine, but returning members are skipped (M7). A daily-only Vercel Hobby cron would send reminders late (already documented in the README).
- Processor routing and volume guard: logic is correct, but it fails open past 1,000 orders (H7) and the mock Braintree can take real traffic (H6).
- Admin MRR: annual/12 and gift exclusion are correct. **Wrong** for cancel-at-period-end members, dashboard refunds, >1000 rows and duplicate fulfilment (H7, H8, H12).

**Compliance logic**
- Claims scanner: **bypassable** (H10).
- Reviewer flag: request-controlled and paraphrasable (M4). The app side is correctly gated on `REVIEWER_SIGNED` plus reviewer names.
- AI labels in packaging: TikTok `is_aigc` and YouTube `containsSyntheticMedia` are enforced (and checked in the n8n pass 2). IG/FB depend on C2PA with a dev cert (M10).
- No condition words in CAPI names or URLs: **OK.** There are only 4 standard event names, source URLs are aliased (`/q/a`, `/q/b`, `/checkout`, `/upsell`), and custom fields containing condition words are dropped. Note that the real gut-quiz path contains "gut" and would leak if a browser pixel were ever added.

**Reliability**
- n8n ↔ workers: all 7 worker calls use `X-Worker-Token` header credentials and the paths match the FastAPI routes. All 8 RPCs and 5 REST tables exist in `schema.sql`. There are no dangling connections, and `test_workflow.py` passes. See L11 for retries and the error-workflow placeholder.
- App code ↔ migrations: every column and enum in `db/types.ts` matches the two migrations (including `outbox.status='skipped'`). The cross-schema `orders` collision is H11.
- Dead links: none. Every `href`, `redirect` and form action resolves to a route or a valid dynamic segment.
- Error handling: the webhook returns 500 so Stripe retries (good), but "membership not found" events are marked processed (C4). Upsell and worker error paths are covered in M8 and L12.

**Accessibility and design**
- Gray text: **none.** The Tailwind theme has no gray scales, there are no gray/slate/zinc/neutral/opacity classes, and every palette pair measured ≥ 5.2:1 (e.g. persimmon on paper 5.78, rice on jade 8.05). All 26 screenshots report `gray: []`.
- Targets: buttons and choices ≥ 60 px, fields 56 px, checkboxes 28 px, 3 px focus ring. OK.
- Font sizes: base text 20–21 px. Exceptions are in L9 (chart axis about 11 px on mobile, 14 px AI badge).
